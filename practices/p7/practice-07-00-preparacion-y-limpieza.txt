EJECUCION DE LOS ARCHIVOS POWERSHELL

Los comandos utilizan un proceso independiente de PowerShell.
ExecutionPolicy Bypass se limita a ese proceso.
No se modifica la politica permanente del equipo.
Se comprueba el codigo de salida inmediatamente despues.

PRACTICA 07.00 - PREPARACION Y LIMPIEZA
Modulos 6 y 7: Performance Tuning y Replicacion
PostgreSQL DBA Administration

REGLA PARA COPIAR COMANDOS

Ejecutar SQL dentro de psql y comandos Docker en PowerShell.
No copiar los prompts ni las explicaciones.

Los metacomandos de psql se ejecutan INDIVIDUALMENTE.
Esto incluye \q, \set y la sentencia que termina con \gset.
Pegar esa instruccion sola, pulsar Enter y esperar el prompt
antes de pegar la siguiente consulta.

Los bloques que contienen solamente SQL pueden pegarse completos.
Un prompt con * indica una transaccion abierta.
Un prompt con - indica una sentencia incompleta.
Si hay texto accidental pendiente, pulsar Ctrl+C y esperar
el prompt antes de pegar nuevamente el SQL.


OBJETIVO

Construir un laboratorio independiente con dos instancias.
Preparar todos los datos antes de iniciar los ejercicios.
Cerrar o reconstruir el laboratorio de manera controlada.

SITUACION

Una empresa necesita consultar pedidos, registrar pagos
y continuar trabajando cuando su principal deja de responder.

Los escenarios forman UNA sola practica.
Ejecutarlos en orden: 07.01, 07.02 y 07.03.

Finalizar transacciones pendientes con COMMIT o ROLLBACK.

Para retirar exclusivamente el contenedor de validacion:

& {
    $ErrorActionPreference = "Stop"

El script verifica nombre, etiqueta, montajes y estado.
Si el servidor esta funcionando, lo detiene primero.
Si falla el cierre o la copia, conserva el contenedor.

No elimina temp ni el contenedor temporal anterior
curso-integrado-validacion.
Esas limpiezas se gestionan por separado.
