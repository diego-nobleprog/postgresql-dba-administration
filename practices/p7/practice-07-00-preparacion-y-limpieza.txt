PRACTICA 07.00 - PREPARACION Y ELIMINACION DEL LABORATORIO
Modulos 6 y 7: Performance Tuning y Replicacion
PostgreSQL DBA - Administracion, Performance, Backup, Replicacion y Alta Disponibilidad

OBJETIVO

Preparar un laboratorio con dos instancias PostgreSQL que permita
analizar consultas lentas, observar la replicacion y simular la falla
del servidor principal. Los ejercicios se realizan en este orden:
07.01 -> 07.02 -> 07.03. Los resultados de cada escenario se conservan
para el siguiente.


- Escenario 1 - La consulta lenta
Diagnosticar, optimizar y verificar la mejora en una réplica

- Escenario 2 - La base de datos bajo actividad
Transacciones, locks, WAL y sincronización de datos

- Escenario 3 - El servidor principal falla
Promoción de standby, recuperación del servicio y verificación del rendimiento


AMBIENTE QUE SE PREPARA

- Windows PowerShell y Docker Desktop.
- Imagen existente: postgresql-dba:18-p1.
- Contenedor: p7-integrado-lab.
- PostgreSQL A: principal; puerto interno 5547; lectura y escritura.
- PostgreSQL B: standby; puerto interno 5548; solo lectura al inicio.
- Base de datos: nobleprog_integrado.
- Esquema: negocio. Tablas: clientes y pedidos.
- Datos iniciales: 3 clientes y 50004 pedidos (4 recientes y 50000 historicos).
- Total inicial de pedidos pagados recientes: 900.

Las instancias A y B funcionan dentro del mismo contenedor. Esta
arquitectura sirve para practicar replicacion y promocion de standby,
pero no representa dos servidores fisicos independientes.

QUE HACE CADA ARCHIVO DE practices/p7/scripts

ARCHIVOS DEL RECORRIDO

01-create-docker-laboratory.ps1
  Crea el contenedor, copia los archivos necesarios y deja preparadas
  las instancias PostgreSQL A y B con los datos iniciales.

02-simulate-primary-server-failure.sh
  En el escenario 07.03 comprueba la sincronizacion y detiene A para
  que se pueda practicar la promocion del standby B.

03-restore-initial-laboratory-state.sh
  Reconstruye A y B con los datos originales si se necesita repetir
  la practica. No se requiere para iniciar ni para eliminar el ambiente.

04-remove-docker-laboratory.ps1
  Cierra las instancias y elimina el contenedor del laboratorio.

ARCHIVOS AUXILIARES (NO SE EJECUTAN POR SEPARADO EN ESTA GUIA)

aux-initialize-docker-container.sh
  Inicia la preparacion dentro del contenedor.

aux-shared-environment-functions.sh
  Reune variables, conexiones y funciones compartidas entre scripts.

aux-create-tables-and-load-sample-data.sql
  Crea las tablas de negocio y carga los pedidos de ejemplo e historicos.

aux-configure-primary-and-standby.sh
  Inicializa A, crea B a partir de un respaldo fisico y configura
  la replicacion continua de WAL.

aux-verify-standby-synchronization.sh
  Comprueba que B ya reprodujo los cambios WAL confirmados en A.

aux-query-recent-paid-orders.sql
  Consulta los pedidos pagados recientes, uno por uno, con su cliente.

aux-report-paid-orders-by-customer.sql
  Agrupa los pedidos pagados por cliente y calcula cantidades y totales.

aux-stop-postgresql-instances.sh
  Detiene ordenadamente las instancias PostgreSQL cuando corresponde.

aux-validate-integrated-laboratory.sh
  Comprueba automaticamente el funcionamiento de los tres escenarios.
  No forma parte del recorrido manual de los participantes.

============================================================
1. INICIAR EL LABORATORIO
============================================================

Desde PowerShell, situarse en la raiz del repositorio:
C:\Users\student\Desktop\postgresql-dba-administration

Usar la rama p7 y tener Docker Desktop encendido y la imagen
postgresql-dba:18-p1 disponible.

COMANDO - POWERSHELL

powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\practices\p7\scripts\01-create-docker-laboratory.ps1" -Mode manual

RESULTADO ESPERADO

LISTO PARA CLASE: CARGA INICIAL PRESENTE; EJERCICIOS SIN EJECUTAR.

PostgreSQL A esta disponible como principal y PostgreSQL B como
standby. Los ejercicios 07.01, 07.02 y 07.03 pueden comenzar.

============================================================
2. ELIMINAR EL LABORATORIO
============================================================

Realizar este paso despues de terminar los tres escenarios y cerrar
las sesiones abiertas. Se eliminaran el contenedor y los datos
almacenados dentro de el; no se borran los archivos del repositorio.

COMANDO - POWERSHELL

powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\practices\p7\scripts\04-remove-docker-laboratory.ps1" -Name p7-integrado-lab

RESULTADO ESPERADO
