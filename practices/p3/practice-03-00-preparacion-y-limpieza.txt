Preparar un ambiente reproducible para investigar procesos,

Este laboratorio utiliza una base de datos independiente.
No modificar nobleprog_architecture_lab.

--------------------------------------------------------------------
1. HISTORIA EMPRESARIAL
--------------------------------------------------------------------

Una empresa comercial administra un catalogo de productos y
registra pedidos de sus clientes.

El equipo DBA necesita investigar cuatro situaciones:

A. Una aplicacion abre varias conexiones simultaneas.
B. Un reporte de ventas necesita ordenar miles de pedidos.
C. Dos usuarios consultan y modifican un mismo registro.
D. Se realizan operaciones y necesitamos conocer su
   almacenamiento y persistencia.

En lugar de construir cuatro ambientes diferentes, utilizaremos
la misma base y relacionaremos los resultados.

--------------------------------------------------------------------
2. COMPONENTES DEL AMBIENTE
--------------------------------------------------------------------

Contenedor: postgresql-dba
Version: PostgreSQL 18.6
Base: nobleprog_architecture_scenarios
Esquema: operaciones

Tablas:
productos  - catalogo de 1000 productos.
pedidos    - 50000 pedidos iniciales.
mvcc_demo  - registro para observar concurrencia.

Las practicas pueden generar cambios adicionales. Por eso existen
scripts de restauracion y limpieza.

--------------------------------------------------------------------
3. ANTES DE COMENZAR: VERIFICAR EL CONTENEDOR
--------------------------------------------------------------------

Desde PowerShell:

Set-Location "C:\Users\student\Desktop\postgresql-dba-administration"

docker ps --filter "name=postgresql-dba"

docker exec -u postgres postgresql-dba postgres --version

docker exec -u postgres postgresql-dba pg_isready -U postgres

INTERPRETACION:

El contenedor debe estar en estado Up.
La version esperada es PostgreSQL 18.6.
pg_isready debe indicar accepting connections.

Si alguna comprobacion falla, no continuar con la carga.

--------------------------------------------------------------------
4. CREAR LA BASE DE DATOS
--------------------------------------------------------------------

Desde PowerShell, en la raiz del repositorio:

Get-Content -Raw ".\practices\p3\scripts\00-create-database.sql" | docker exec -i -u postgres postgresql-dba psql -X -v ON_ERROR_STOP=1 -U postgres -d postgres

QUE HACE:

1. Consulta si existe la base del laboratorio.
2. Crea la base si no existe.
3. Verifica su presencia en pg_database.

No elimina bases existentes.

--------------------------------------------------------------------
5. CARGAR LA INFORMACION INICIAL
--------------------------------------------------------------------

Desde PowerShell:

Get-Content -Raw ".\practices\p3\scripts\01-load-data.sql" | docker exec -i -u postgres postgresql-dba psql -X -v ON_ERROR_STOP=1 -U postgres -d nobleprog_architecture_scenarios

ADVERTENCIA:

El script recrea las tablas del esquema operaciones.
No debe ejecutarse mientras existan sesiones trabajando sobre
esas tablas.

La carga utiliza generate_series(), funcion de PostgreSQL que
genera secuencias de valores sin requerir archivos CSV externos.

Se ejecuta ANALYZE para actualizar estadisticas del optimizador.

RESULTADO ESPERADO:

productos | pedidos | mvcc
----------+---------+-----
1000      | 50000   | 1

--------------------------------------------------------------------
6. ENTRAR A POSTGRESQL INTERACTIVAMENTE
--------------------------------------------------------------------

Desde PowerShell:

docker exec -it -u postgres postgresql-dba psql -X -U postgres -d nobleprog_architecture_scenarios

A partir de aqui, los comandos SQL se ejecutan directamente en psql.

Verificar:

SELECT current_database();

SELECT current_schema();

SELECT count(*) FROM operaciones.productos;

SELECT count(*) FROM operaciones.pedidos;

SELECT * FROM operaciones.mvcc_demo;

INTERPRETACION:

current_database() identifica la base de la conexion.
current_schema() puede mostrar public; eso es normal.
Las tablas del ejercicio se consultan con operaciones.nombre.

SALIR DE PSQL:

\q

--------------------------------------------------------------------
7. COMO EJECUTAR LOS SCRIPTS DESDE PSQL
--------------------------------------------------------------------

En una sesion psql, se puede ejecutar un script mediante \i.

El archivo SQL reside en Windows y psql se ejecuta dentro del
contenedor. Por tanto, la ruta Windows NO es visible directamente
desde esa sesion.

Para evitar confusiones, ejecutaremos los scripts SQL desde
PowerShell utilizando Get-Content y docker exec -i.

Las consultas de investigacion se ejecutaran desde psql
interactivo.

--------------------------------------------------------------------
11. COMPARACION CON ORACLE
--------------------------------------------------------------------

PostgreSQL database:
No equivale directamente a una instancia Oracle.

PostgreSQL schema:
Agrupa objetos mediante un namespace. En Oracle, los esquemas
estan vinculados a usuarios.

generate_series():
Permite generar filas. En Oracle, un ejemplo comparable utiliza
CONNECT BY LEVEL o una consulta recursiva.

ANALYZE:
Actualiza estadisticas del optimizador. En Oracle se utilizan
mecanismos como DBMS_STATS.

La preparacion es parte del trabajo DBA: un experimento solo
es util si conocemos su estado inicial y podemos repetirlo.
