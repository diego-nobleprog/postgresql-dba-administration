PRACTICA 06.00 - PREPARACION Y LIMPIEZA
Modulo 5: Mantenimiento y Autovacuum
PostgreSQL DBA Administration

Esta guia permite preparar el laboratorio necesario para las
practicas 06.01 a 06.05 y eliminarlo cuando terminen.

El laboratorio utiliza un contenedor PostgreSQL independiente
para no modificar el servidor principal del curso.

Todos los comandos se ejecutan desde Windows PowerShell 5.1.

Repositorio:
C:\Users\student\Desktop\postgresql-dba-administration

Rama requerida: p6


============================================================
1. CREAR TODO EL LABORATORIO
============================================================

OBJETIVO

Construir un ambiente PostgreSQL desde cero con las tablas,
datos y configuraciones necesarios para las cinco practicas.

No se necesita crear bases, tablas ni cargar datos manualmente.


QUE SE VA A CREAR

Contenedor Docker:
p6-maintenance-lab

Imagen:
postgresql-dba:18-p1

Base de datos:
nobleprog_maintenance_scenarios

Esquema:
maintenance

Tablas y datos iniciales:

mvcc_work       10000 registros
bloat_work      30000 registros
distribution    20000 registros
auto_work           0 registros
freeze_work      1000 registros

La tabla distribution contiene inicialmente:
- 100 registros con estado 'raro'.
- 19900 registros con estado 'normal'.

Cada tabla se utiliza para un escenario diferente.

El laboratorio utiliza un servidor PostgreSQL separado,
sin publicar puertos en Windows y sin acceso de red.

Los scripts de preparacion ya existen en:
practices/p6/scripts/


COMANDO - POWERSHELL

Ejecutar el siguiente bloque completo:

& {
    $ErrorActionPreference = "Stop"

    Set-Location "C:\Users\student\Desktop\postgresql-dba-administration"

    # Verificar que estamos en la rama correcta.
    $branch = git branch --show-current

    if ($LASTEXITCODE -ne 0 -or $branch -ne "p6") {
        throw "Debes estar en la rama p6."
    }

    # Evitar sobrescribir un laboratorio existente.
    $name = "p6-maintenance-lab"

    $names = @(docker container ls -a --format '{{.Names}}')

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo consultar Docker."
    }

    if ($names -contains $name) {
        throw "El laboratorio ya existe. No se sobrescribira."
    }

    # Crear un contenedor independiente para P6.
    docker create --name p6-maintenance-lab --network none --label nobleprog.p6.lab=true --entrypoint /bin/bash postgresql-dba:18-p1 /tmp/p6-scripts/00-start-container.sh manual

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo crear el contenedor."
    }

    # Copiar los scripts necesarios al contenedor.
    docker cp ".\practices\p6\scripts" "p6-maintenance-lab:/tmp/p6-scripts"

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudieron copiar los scripts."
    }

    # Iniciar PostgreSQL y preparar los datos.
    docker start p6-maintenance-lab

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo iniciar el contenedor."
    }

    # Esperar a que termine la preparacion.
    $ready = $false

    for ($attempt = 1; $attempt -le 90; $attempt++) {
        $logs = @(docker logs p6-maintenance-lab)

        if ($LASTEXITCODE -ne 0) {
            throw "No se pudieron consultar los logs."
        }

        if ($logs -contains "LABORATORIO MANUAL PREPARADO") {
            $ready = $true
            break
        }

        Start-Sleep -Seconds 1
    }

    # Mostrar el resultado de la preparacion.
    docker logs p6-maintenance-lab

    if ($LASTEXITCODE -ne 0 -or -not $ready) {
        throw "No se confirmo la preparacion del laboratorio."
    }

    # Confirmar que PostgreSQL permanece iniciado.
    docker exec -u postgres p6-maintenance-lab pg_ctl -D /tmp/nobleprog-p6-lab/data status

    if ($LASTEXITCODE -ne 0) {
        throw "PostgreSQL no esta disponible."
    }

    Write-Output "LABORATORIO P6 PREPARADO CORRECTAMENTE"
}


QUE HIZO EL COMANDO

1. Comprobo que estamos en la rama p6.

2. Verifico que no exista otro contenedor con el mismo nombre.

3. Creo un contenedor independiente usando la imagen
   PostgreSQL que ya utilizamos durante el curso.

4. Copio los scripts del repositorio al contenedor.

5. Inicio el contenedor y ejecuto automaticamente los scripts
   de inicializacion y preparacion.

6. PostgreSQL creo su propio directorio de datos y su
   configuracion independiente.

7. Se creo la base nobleprog_maintenance_scenarios.

8. Se creo el esquema maintenance con sus cinco tablas.

9. Se insertaron los registros iniciales.

10. Se configuraron las tablas para controlar cuando
    interviene el mantenimiento automatico.

11. Se verifico que PostgreSQL continuara funcionando.


RESULTADO ESPERADO

Al finalizar debe aparecer:

LABORATORIO MANUAL PREPARADO

Y posteriormente:

LABORATORIO P6 PREPARADO CORRECTAMENTE

El servidor queda encendido y listo para comenzar las
practicas 06.01 a 06.05.


COMO CONECTARSE A POSTGRESQL

Desde cualquier terminal PowerShell ejecutar:

docker exec -it -u postgres p6-maintenance-lab psql -X -h /tmp/nobleprog-p6-lab/socket -p 5546 -U postgres -d nobleprog_maintenance_scenarios

Una vez dentro de psql, podemos comprobar las tablas:

SELECT COUNT(*) FROM maintenance.mvcc_work;

SELECT COUNT(*) FROM maintenance.bloat_work;

SELECT COUNT(*) FROM maintenance.distribution;

SELECT COUNT(*) FROM maintenance.auto_work;

SELECT COUNT(*) FROM maintenance.freeze_work;

Para salir de psql:

\q

NOTAS IMPORTANTES

- Todos los datos necesarios ya estan preparados.

- No se necesita ejecutar manualmente ningun archivo SQL
  para cargar las tablas iniciales.

- Para las practicas que necesiten varias sesiones,
  abrir otras terminales PowerShell y repetir la conexion.

- El puerto 5546 pertenece al PostgreSQL interno del
  contenedor. No se publica en Windows.

- El contenedor principal postgresql-dba no se modifica.

- Si queremos repetir todas las practicas desde cero,
  primero debemos limpiar el laboratorio y volverlo a crear.


============================================================
2. LIMPIAR TODO EL LABORATORIO
============================================================

OBJETIVO

Eliminar completamente el ambiente creado para P6,
sin modificar los contenedores ni las bases de datos
utilizadas en otras practicas.


QUE SE VA A ELIMINAR

- Contenedor p6-maintenance-lab.
- Servidor PostgreSQL independiente de P6.
- Base nobleprog_maintenance_scenarios.
- Esquema maintenance.
- Las cinco tablas y todos sus registros.
- Archivos temporales y evidencias internas del contenedor.

Los scripts y documentos del repositorio NO se eliminan.

IMPORTANTE:

Esta limpieza descarta todos los datos del laboratorio P6.
Debe ejecutarse cuando hayamos terminado los ejercicios.


ANTES DE LIMPIAR

Si tenemos terminales abiertas dentro de psql:

1. Finalizar las transacciones pendientes con COMMIT
   o ROLLBACK, segun corresponda.

2. Salir de cada conexion utilizando:

\q

3. Regresar a PowerShell.


COMANDO - POWERSHELL

Ejecutar el siguiente bloque completo:

& {
    $ErrorActionPreference = "Stop"

    Set-Location "C:\Users\student\Desktop\postgresql-dba-administration"

    $name = "p6-maintenance-lab"

    # Comprobar que existe el contenedor del laboratorio.
    $names = @(docker container ls -a --format '{{.Names}}')

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo consultar Docker."
    }

    if ($names -notcontains $name) {
        throw "No existe el contenedor del laboratorio P6."
    }

    # Confirmar que pertenece a nuestro laboratorio.
    $raw = @(docker inspect $name)

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo inspeccionar el contenedor."
    }

    $info = @((($raw -join [Environment]::NewLine) | ConvertFrom-Json))[0]

    if ($info.Config.Labels.'nobleprog.p6.lab' -ne "true") {
        throw "El contenedor no pertenece al laboratorio P6."
    }

    # Restaurar configuraciones y detener PostgreSQL.
    docker exec -u postgres $name /bin/bash /tmp/p6-scripts/99-cleanup-lab.sh

    if ($LASTEXITCODE -ne 0) {
        throw "Fallo la restauracion. No se eliminara el contenedor."
    }

    # Verificar que el servidor PostgreSQL se detuvo.
    docker exec $name test ! -e /tmp/nobleprog-p6-lab/data/postmaster.pid

    if ($LASTEXITCODE -ne 0) {
        throw "No se confirmo que PostgreSQL este detenido."
    }

    # Eliminar exclusivamente el contenedor P6.
    docker rm -f $name

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo eliminar el contenedor."
    }

    # Comprobar que el contenedor ya no existe.
    $remaining = @(docker container ls -a --format '{{.Names}}')

    if ($LASTEXITCODE -ne 0) {
        throw "No se pudo comprobar la limpieza."
    }

    if ($remaining -contains $name) {
        throw "El contenedor sigue existiendo."
    }

    Write-Output "LABORATORIO P6 ELIMINADO CORRECTAMENTE"
}


QUE HIZO EL COMANDO

1. Comprobo que existe el contenedor P6.

2. Verifico su etiqueta para evitar eliminar otro
   contenedor accidentalmente.

3. Ejecuto el script de limpieza del laboratorio.

4. Restauro las opciones de las tablas y los parametros
   globales modificados durante las practicas.

5. Comprobo que las configuraciones fueran restauradas.

6. Detuvo el servidor PostgreSQL.

7. Verifico que PostgreSQL estuviera detenido.

8. Elimino el contenedor y sus datos internos.

9. Comprobo que el contenedor ya no existiera.


RESULTADO ESPERADO

Al finalizar debe aparecer:

LABORATORIO P6 ELIMINADO CORRECTAMENTE


NOTAS IMPORTANTES

- La limpieza solamente afecta al contenedor de P6.

- El servidor principal postgresql-dba permanece intacto.

- No se eliminan imagenes Docker ni volumenes de otros
  laboratorios.

- No se modifican archivos del repositorio.

- No se conservan los datos del laboratorio eliminado.

- La restauracion de configuraciones se realiza antes
  de eliminar el contenedor, para comprobar que el

- Si la restauracion falla, el comando conserva el
